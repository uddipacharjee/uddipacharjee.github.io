Spring AI: RAG and an MCP Server in Spring Boot

By Uddip Acharjee Shuvo28 October 202610 min read

A language model knows a lot about the world and nothing about your runbooks, architecture decisions or API docs. Two techniques close that gap. Retrieval-augmented generation (RAG) finds the relevant parts of your documents and hands them to the model with the question. The Model Context Protocol (MCP) lets AI assistants, such as coding agents in your IDE, call tools you provide, like a search over those same documents.

Spring AI makes both feel like ordinary Spring code: auto-configured clients, properties and annotations. This post builds a small document search service with RAG on PostgreSQL, then exposes it as an MCP server.

Versions in this post

Spring AI 2.0.2, the current stable release, which requires Spring Boot 4.0 or 4.1. If you are on Spring Boot 3, you are on Spring AI 1.x. The last section lists the renames that matter.

How RAG works

RAG has two halves. Ingestion runs whenever your documents change: split them into chunks, turn each chunk into a vector with an embedding model, and store the vectors. The question path runs on every request: embed the question, find the most similar chunks, put them in the prompt, and let the chat model answer from them.

Dependencies

The OpenAI starter provides both the chat model and the embedding model. Swap in spring-ai-starter-model-ollama to run locally. Note spring-ai-vector-store-advisor: it provides QuestionAnswerAdvisor, and no starter pulls it in for you.

PostgreSQL as the vector store

PGVector adds a vector column type and similarity search to PostgreSQL, so your embeddings can live next to the rest of your data. The pgvector/pgvector image has the extension built in:

initialize-schema is off by default; with it on, Spring AI creates the vector_store table at startup. The vector dimensions come from the embedding model. If you later switch embedding models, the dimensions change too, so drop and re-create the table and ingest everything again.

Ingesting documents

A DocumentReader turns files into Documents, a splitter cuts them into chunks, and the vector store embeds and saves them in one call:

Tika reads PDF, Word, HTML and many other formats; for plain text, TextReader is enough. Chunk size is a trade-off: small chunks match precisely but lose context, while large ones carry context but dilute the match. Around 800 tokens, the default, is a reasonable start. Re-ingesting a file adds new chunks next to the old ones, so delete a document’s previous chunks before loading a new version.

Answering questions

ChatClient is Spring AI’s fluent API for calling a model, and advisors wrap a call with extra behaviour. QuestionAnswerAdvisor is the RAG advisor: it searches the vector store with the user’s question and adds the matching chunks to the prompt.

topK caps how many chunks go into the prompt, and similarityThreshold drops chunks that are only loosely related, so the model is not distracted by noise. Both are worth tuning against a set of real questions. To narrow the search per request, pass a metadata filter:

Exposing search as an MCP tool

RAG answers questions inside your application. MCP turns it around: an assistant your developers already use can call your search directly, and decide for itself when to.

Add the MCP server starter for Spring MVC:

Streamable HTTP is the default transport in Spring AI 2, and the endpoint is /mcp. Then write the tool as an annotated method on any bean:

@McpTool and @McpToolParam live in org.springframework.ai.mcp.annotation, and Spring AI finds them on startup. Write the descriptions for the model, not for a colleague: they are all it has to decide when the tool is useful and what to pass in. If you also want the method available to your own ChatClient, annotate it with Spring AI’s @Tool instead and register it with a MethodToolCallbackProvider bean, which the MCP server exposes as well.

To try it, point any MCP client that supports Streamable HTTP at http://localhost:8080/mcp. The MCP Inspector (npx @modelcontextprotocol/inspector) lists the tools and lets you call them by hand.

Secure it before it leaves your machine

The HTTP transport has no authentication by default, and this tool returns internal documents to whoever asks. Put the endpoint behind Spring Security before deploying it anywhere shared.

Coming from Spring AI 1.x

  • Spring AI 2 requires Spring Boot 4. Spring AI 1.x stays on Boot 3.
  • The advisor artifact was renamed from spring-ai-advisors-vector-store to spring-ai-vector-store-advisor; the package is the same.
  • Model property keys lost their .options segment: spring.ai.openai.chat.options.model is now spring.ai.openai.chat.model.
  • The MCP annotations moved from org.springaicommunity.mcp into org.springframework.ai.mcp.annotation, and the MCP server now defaults to Streamable HTTP; SSE is deprecated.
  • Builders replace constructors: new TokenTextSplitter() is deprecated, and QuestionAnswerAdvisor is created only through its builder.
  • Pre-1.0 starter names such as spring-ai-openai-spring-boot-starter are long gone; starters are now named spring-ai-starter-model-* and spring-ai-starter-vector-store-*.

Checklist

  • BOM, model starter, PGVector starter, and the vector-store advisor artifact.
  • initialize-schema=true for the first run, and a re-ingest whenever the embedding model changes.
  • Chunks around 800 tokens to start, old chunks deleted on re-ingest.
  • QuestionAnswerAdvisor with topK and a similarity threshold tuned on real questions.
  • An MCP tool with descriptions written for the model.
  • Authentication in front of /mcp before it is shared.
