Which JDK Distribution Should You Use in 2026?

By Uddip Acharjee Shuvo28 October 202615 min read

Every JDK in this guide is built from the same OpenJDK source code, and the certified ones run your application the same way. So why are there so many, and does the choice matter? It does, but not for the reasons people expect. What differs is how long each vendor keeps shipping free security updates, the licence you run under in production, the platforms and container images on offer, and who you can call when something breaks.

This guide compares ten JDK distributions on exactly those points, then covers GraalVM and what the choice means for a Spring Boot project. Support dates, licences and images come from each vendor’s own pages, checked in October 2026.

What actually differs between JDKs

  • How long updates stay free. Each vendor decides how long it patches each long-term support (LTS) release. For Java 25 the published dates range from early 2026 to late 2032.
  • The production licence. Most builds use the GPLv2 with the Classpath Exception and are free forever. Oracle JDK is free only for a limited time per release.
  • Certification. Builds that pass the Java Technology Compatibility Kit (TCK, or JCK) are certified as compatible with the Java SE specification.
  • Platforms. Alpine (musl), Windows on ARM, RISC-V, s390x and AIX are where distributions differ most.
  • Container images. Official, maintained images and their base operating systems.
  • Paid support. Whether you can buy it, and whether the price is published.
  • Extras. JavaFX, CRaC for fast startup, the OpenJ9 JVM, or native images.

Which Java version?

The LTS releases are Java 8, 11, 17, 21 and 25. Java 27, released in September 2026, is a feature release that only gets about six months of updates, and the next LTS is planned to be Java 29 in September 2027. For a new project, choose Java 25. Spring Boot 3.x and 4.x both need Java 17 or later.

Which one should you choose?

  • No special requirements: Eclipse Temurin. It is vendor-neutral, free, and the default almost everywhere.
  • Long free updates with a published date: Amazon Corretto, with Java 25 patched until October 2032.
  • Running on AWS: Amazon Corretto. On Azure: Microsoft Build of OpenJDK.
  • RHEL or OpenShift with a Red Hat subscription: Red Hat build of OpenJDK.
  • Spring Boot images built with buildpacks: BellSoft Liberica, which they already use.
  • Windows on ARM: Microsoft Build of OpenJDK, Azul Zulu or Liberica.
  • Low memory use in dense container deployments: IBM Semeru, with OpenJ9.
  • Paid support including Java 6 or 7: Azul.
  • Inside SAP: SapMachine.
  • Oracle JDK: only if you have a Java SE subscription, or you are on the newest releases and will move on before the free period ends.

Amazon’s OpenJDK build, which it runs on thousands of its own production services. It publishes some of the longest free update commitments of any vendor, and sometimes ships fixes before they reach the matching OpenJDK update release.

Key features

What about GraalVM?

GraalVM used to be pitched as a faster, drop-in JDK. That changed in 2025. GraalVM for JDK 24 was the last version licensed and supported as part of Oracle’s Java SE products, and the optional Graal JIT compiler was removed from Oracle JDK 25.

GraalVM itself continues in two editions, both including Native Image. Oracle GraalVM is free under the GraalVM Free Terms and Conditions, except its 17.0.13 and 21.0.13 updates and later, which moved to an OTN licence. GraalVM Community Edition is GPLv2 with the Classpath Exception. Since 25.1, both ship a new feature release every month rather than every six months.

Reach for GraalVM when you want a native executable with fast startup and low memory, for example for a CLI tool or a scale-to-zero service. BellSoft’s Liberica Native Image Kit and Red Hat’s Mandrel are downstream builds of GraalVM CE aimed at exactly that. For everything else, use one of the regular JDKs above.

Choosing a JDK for Spring Boot

Spring Boot does not recommend a vendor; its only requirement is Java 17 or later. Spring Boot 3.5 supports up to Java 25, and Spring Boot 4.x up to Java 27. Any certified build runs your application the same way, so the decision mostly comes down to how you build and deploy.

Container images from bootBuildImage

./gradlew bootBuildImage and mvn spring-boot:build-image use Paketo buildpacks, which install BellSoft Liberica by default. Frequently asked questions

Is OpenJDK free for commercial use?

Yes. Builds released under the GPLv2 with the Classpath Exception, such as Eclipse Temurin, Amazon Corretto, Azul Zulu, Microsoft Build of OpenJDK, SapMachine and IBM Semeru's Open Edition, are free to use in production. BellSoft Liberica is also free for production. Oracle JDK is the exception: it is free under its NFTC licence only for a limited period per release.

Is Oracle JDK free?

Partly. As of October 2026, Oracle JDK 25 and 27 are free for production under the No-Fee Terms and Conditions licence; for Java 25 that lasts until September 2028. Oracle JDK 21 updates from 21.0.13 (October 2026), 17 updates from 17.0.13, and all 8 and 11 updates are under the OTN licence, which needs a paid Java SE subscription for production use.

What is the difference between OpenJDK and Oracle JDK?

Both are built from the OpenJDK source code. The differences are the licence, how long free updates last, packaging such as installers, and commercial support. For running applications, a TCK-certified OpenJDK build behaves the same as Oracle JDK.

Which JDK should I use with Spring Boot?

Any TCK-certified build works; Spring Boot does not recommend a vendor. Spring Boot 3.x and 4.x need Java 17 or later; Boot 3.5 supports up to Java 25 and Boot 4.x up to Java 27. If you build images with bootBuildImage, the default Paketo buildpacks install BellSoft Liberica, and you can switch to another vendor's buildpack.

Which Java version should a new project use?

Java 25, the newest LTS release, released in September 2025. Java 27 is a feature release that only gets about six months of updates, and the next LTS, Java 29, is planned for September 2027.

Which JDK image should I use in Docker?

Use an actively maintained image and pin the Java version in the tag, for example eclipse-temurin:25-jre, amazoncorretto:25 or mcr.microsoft.com/openjdk/jdk:25-ubuntu. Avoid the deprecated openjdk image on Docker Hub, and don't rely on amazoncorretto:latest, which is Java 8.

Is GraalVM a drop-in replacement for my JDK?

Not anymore in the way it once was. Oracle detached GraalVM from its Java SE products after GraalVM for JDK 24, and GraalVM now ships monthly feature releases focused on Native Image and other languages. Use it, or a downstream build such as Liberica Native Image Kit or Mandrel, when you want native executables; use a regular JDK otherwise.
